# Contributing

## Branching

- `main` stays stable.
- Use short-lived feature branches for each task.
- Merge small pull requests frequently.

## Commit Style

- Use clear commit messages that describe the outcome, not just the file touched.
- Keep unrelated changes out of the same commit.

## Pull Requests

- Explain what changed, why it changed, and how it was tested.
- Call out risk areas and any follow-up work.

## Documentation

- Update docs when behavior, architecture, setup, or operating procedures change.
